## Buildroot

Buildroot 是用来生成嵌入式 Linux 系统的工具。

在当前板子上，它表现为一个很轻的 Linux 系统：

- 没有 Ubuntu 桌面。
- 包管理能力弱。
- 常见命令和服务被裁剪。
- 更接近产品固件。

当前意义：

```text
板子出厂系统是 Buildroot。
我们在它上面验证 Camera、OpenCV、RKNN、Nginx、FFmpeg。
```

外部资料：

- [Buildroot Manual](https://buildroot.org/downloads/manual/manual.html)

## MIPI Camera

MIPI Camera 通常指通过 MIPI CSI 接口接入 SoC 的摄像头。

当前链路：

```text
IMX415 sensor -> MIPI CSI -> RK3568 ISP -> V4L2 video node
```

优势：

- 带宽高，适合高分辨率 Camera。
- 延迟低，适合实时视频。
- 是手机、车载、嵌入式视觉里常见的 Camera 接口。
- 能直接进入 SoC 的 ISP，比 USB Camera 更接近真实产品形态。

注意：

```text
Camera 的 MIPI CSI 是输入。
屏幕的 MIPI DSI 是输出。
这两个都叫 MIPI，但方向和用途不同。
```

## RKISP

RKISP 是 Rockchip 的图像信号处理链路。

它负责把 sensor 输出的原始图像转换成应用更容易处理的视频格式。

当前现象：

```text
/dev/video0 显示为 rkisp_mainpath。
```

理解方式：

```text
sensor 不是直接给 OpenCV。
中间经过 CSI、ISP、V4L2，再给应用层。
```

## V4L2

V4L2 是 Linux 用户态访问视频设备的标准接口。

典型设备：

```text
/dev/video0
/dev/video1
/dev/media0
```

当前用途：

- 枚举 Camera。
- 查看支持格式。
- 抓取原始帧。
- 给 GStreamer/OpenCV 提供采集入口。

外部资料：

- [Linux V4L2 用户空间 API](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/v4l2.html)

## Media Controller

Media Controller 用来描述复杂 Camera 拓扑。

当前意义：

```text
/dev/media0 可以帮助理解 sensor、CSI、ISP、video node 之间的连接关系。
```

你现在不用深入 media-ctl 命令。

先知道：

```text
/dev/video0 是数据节点。
/dev/media0 是拓扑节点。
```

## NV12

NV12 是 YUV 4:2:0 图像格式。

数据结构：

```text
先放完整 Y 平面。
再放交错 UV 平面。
```

大小计算：

```text
width * height * 1.5
```

当前例子：

```text
1280 * 720 * 1.5 = 1382400 bytes
```

为什么重要：

```text
Camera 常输出 NV12。
OpenCV/AI 模型通常更喜欢 BGR/RGB。
所以中间需要格式转换。
```

## GStreamer

GStreamer 是多媒体 pipeline 框架。

当前用途：

```text
显式指定 /dev/video0 输出 NV12，再转换成 OpenCV 可用的 BGR。
```

当前成功 pipeline：

```text
v4l2src device=/dev/video0
! video/x-raw,format=NV12,width=1280,height=720
! videoconvert
! video/x-raw,format=BGR
! appsink drop=1 sync=false
```

关键元素：

- `v4l2src` 从 V4L2 设备取帧。
- `video/x-raw` 指定格式和分辨率。
- `videoconvert` 做颜色格式转换。
- `appsink` 把帧交给应用程序。

外部资料：

- [GStreamer Documentation](https://gstreamer.freedesktop.org/documentation/)
- [GStreamer v4l2src](https://gstreamer.freedesktop.org/documentation/video4linux2/v4l2src.html)
- [GStreamer appsink](https://gstreamer.freedesktop.org/documentation/app/appsink.html)

## OpenCV

OpenCV 在当前项目中不是用来做复杂算法。

当前用途：

- 接收 Camera 帧。
- 做 resize、颜色转换。
- 画检测框。
- 保存图片。
- 显示到 MIPI 屏。

关键结论：

```text
cv2.VideoCapture(0) 在当前 RK3568 板端已验证失败。
主路线统一使用 GStreamer pipeline。
```

外部资料：

- [OpenCV VideoCapture](https://docs.opencv.org/4.x/d8/dfe/classcv_1_1VideoCapture.html)

## RKNN

RKNN 是 Rockchip NPU 的模型部署体系。

当前涉及组件：

- `.rknn` 模型文件。
- `rknn-toolkit-lite2` 板端 Python 推理接口。
- `librknnrt.so` 板端 runtime。
- `rknn_server` 板端服务。
- NPU 驱动。

当前已验证：

```text
01_lenet -> [5]: 1.0
YOLOv5 RKNN -> person/bus 检测
```

外部资料：

- [Rockchip RKNN Toolkit2](https://github.com/airockchip/rknn-toolkit2)

## YOLOv5 / YOLOv8n

YOLO 是目标检测模型。

当前区别：

```text
当前板端 Buildroot 4.19 官方资料里可直接复用的是 YOLOv5 RKNN。
最终项目目标可以升级到 YOLOv8n。
```

当前原则：

```text
先用 YOLOv5 跑通系统闭环。
后续再做 YOLOv8n 模型转换和工程升级。
```

## RTMP

RTMP 是一种实时流媒体推流协议。

当前用途：

```text
板端 FFmpeg 把检测后的视频推给本机 Nginx RTMP server。
```

当前 RTMP 地址：

```text
rtmp://127.0.0.1/live/yolo
```

## HLS

HLS 是基于 HTTP 的流媒体播放方式。

文件形态：

```text
yolo.m3u8
yolo-0.ts
yolo-1.ts
```

当前用途：

```text
Windows 使用 ffplay 访问 http://192.168.0.230/hls/yolo.m3u8。
```

常见问题：

- `.m3u8` 不存在会返回 404。
- 程序没持续运行时，HLS 可能不可用。
- HLS 分片需要关键帧边界，所以编码端要固定 GOP。

外部资料：

- [FFmpeg HLS muxer](https://ffmpeg.org/ffmpeg-formats.html#hls-2)
- [nginx-rtmp-module](https://github.com/arut/nginx-rtmp-module)
