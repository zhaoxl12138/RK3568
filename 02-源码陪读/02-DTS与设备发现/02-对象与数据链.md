## DTS 到 C 对象

```dts
&i2c4 {
    imx415: imx415@1a {
        compatible = "sony,imx415";
        reg = <0x1a>;
        reset-gpios = <&gpio3 RK_PB6 GPIO_ACTIVE_LOW>;
        port { imx415_out: endpoint {
            remote-endpoint = <&mipi_in_ucam1>;
            data-lanes = <1 2 3 4>;
        }; };
    };
};
```

```text
compatible → info.type / dev.of_node → match table
reg        → client->addr = 0x1a
GPIO/clock → probe 阶段按 dev->of_node 申请资源
endpoint   → fwnode 图关系，稍后由 V4L2 Async/Media 驱动解析
```

## 原始代码陪读

```c
struct i2c_client *i2c_new_device(struct i2c_adapter *adap,
                                  const struct i2c_board_info *info)
{
    client = kzalloc(sizeof(*client), GFP_KERNEL); // 直接调用：分配对象
    client->adapter = adap;                        // 对象关系：挂到 I2C4 adapter
    client->addr = info->addr;                     // 字段赋值：保存 0x1a
    client->dev.bus = &i2c_bus_type;                // 对象关系：归属 I2C bus
    client->dev.of_node = of_node_get(info->of_node);// 关联运行时 DTS 节点
    return device_register(&client->dev);           // 直接调用并触发匹配机会
}
```

### C 基础：phandle 不是 C 指针

DTS 中 `<&mipi_in_ucam1>` 编译为 phandle 数值；运行时 OF API 依据该编号找到另一个 `device_node`。驱动再把这种静态引用转换成 C 对象关系。它不是把 C 指针直接存进 DTB。

## 调用类型

- `client->addr = info->addr`：字段赋值。
- `client->adapter = adap`：对象关系。
- `i2c_new_device(...)`：直接调用。
- client 注册后触发 bus match：框架行为。
- endpoint 被 Media 驱动解析并在 `.bound()` 建 Link：后续框架回调，不在 DTB 编译时发生。

## 大白话解释

I2C client 是一张运行时设备卡：写着“我在 I2C4、地址 0x1a、原始档案是哪个 DTS 节点”。GPIO、时钟并没有一次性复制进 client；驱动进入 probe 后拿 `client->dev.of_node` 去各资源框架逐项申请。

## 板端证据边界

```bash
od -An -tx1 /sys/firmware/devicetree/base/i2c@fe5d0000/imx415@1a/reg
cat /sys/bus/i2c/devices/4-001a-1/uevent
media-ctl -p | sed -n '/imx415/,/rockchip-csi2-dphy0/p'
```

- `00 00 00 1a` 能证明 DT `reg` 是大端 cell 值 0x1a。
- `OF_FULLNAME` 能证明 client 关联原节点。
- Media Graph 能证明 endpoint 已被驱动转成运行时 Link。
- 以上仍不能证明该 Link 上有有效 CSI-2 数据包。

## 面试问题

`remote-endpoint` 写成双向引用，是否意味着 DTB 编译后 Media Link 已经存在？

**我的回答：**


<mark>高亮正确答案：不是。双向 endpoint 只是固件中的静态图描述。Sensor、D-PHY 等驱动先各自注册 subdev/entity/pad，V4L2 Async 匹配成功后，bound 回调才调用 media_create_pad_link() 建立运行时 Link。</mark>
