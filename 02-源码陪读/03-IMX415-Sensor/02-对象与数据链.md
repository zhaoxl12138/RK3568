# 03-02 对象与数据链：probe 资源、上电与 Sensor ID

## Source Insight 定位

主文件 `drivers/media/i2c/imx415.c`，依次搜索：

```text
imx415_probe
devm_clk_get
devm_gpiod_get
imx415_configure_regulators
__imx415_power_on
imx415_check_sensor_id
imx415_read_reg
```

DTS 对照：`arch/arm64/boot/dts/rockchip/rk3568-atk-evb1-ddr4-v10.dtsi` 搜 `imx415@1a`。基线根分别是 E 盘 Source Insight 与 WSL SDK。

## `probe()` 从哪里拿到 DTS

```c
static int imx415_probe(struct i2c_client *client,
                        const struct i2c_device_id *id)
{
    struct device *dev = &client->dev;      // 取内嵌的通用 device
    struct device_node *node = dev->of_node;// 对象关系：指向 imx415@1a

    imx415 = devm_kzalloc(dev, sizeof(*imx415), GFP_KERNEL);
    imx415->client = client;                // 私有对象记住 I2C client

    imx415->xvclk = devm_clk_get(dev, "xvclk");
    imx415->reset_gpio = devm_gpiod_get(dev, "reset", GPIOD_ASIS);
    imx415->power_gpio = devm_gpiod_get(dev, "power", GPIOD_ASIS);
}
```

这些 API 是直接调用；资源框架根据 `dev->of_node` 查 `clock-names`、`reset-gpios`、`power-gpios`。这与注册 driver 是两个时间点。

## Sensor ID 代码

```c
ret = imx415_read_reg(client, IMX415_REG_CHIP_ID,
                      IMX415_REG_VALUE_08BIT, &id); // 通过 I2C 直接读取
if (id != CHIP_ID)
    return -ENODEV;                              // 型号不符，probe 失败

dev_info(dev, "Detected imx415 id %06x\n", CHIP_ID);
```

## 调用类型与 C 基础

- `imx415->client = client`：字段赋值/对象关系。
- `devm_clk_get()`、`__imx415_power_on()`：直接调用。
- `imx415_probe()`：I2C Core 框架回调。
- `goto err_power_off`：失败时复用逆序清理路径；不是循环。
- `devm_*` 资源与 device 生命周期绑定，probe 失败或解绑时由 devres 自动释放，但硬件状态仍常需显式关闭。

## 大白话解释

probe 的 `client` 像装好 DTS 指针的工作单。驱动拿这张工作单申请当前板子的时钟、GPIO 和供电控制，再按时序让 Sensor 进入可通信状态，最后读芯片身份证。注册 driver 时没有具体 client，因此不可能提前拿到这些板级资源。

## dummy regulator 的证据边界

当前 DTS 没写 `dvdd-supply`、`dovdd-supply`、`avdd-supply` 时，regulator core 可能给 dummy regulator；软件 enable 可以成功，但 dummy 不产生真实电压。板载模组仍能读 ID，说明真实电源由板级固定供电/LDO 提供。

- 能证明：当前板硬件在基本供电、MCLK、复位和 I2C 条件下返回预期 ID。
- 不能证明：三路芯片电源严格由该 GPIO 控制、Sony 全部时序裕量已验证、MIPI 正在输出。

## 面试问题

读到 `Detected imx415 id 0000e0` 能证明什么，不能证明什么？

**我的回答：**


<mark>高亮正确答案：能证明驱动已进入 probe，Sensor 具备基本供电、时钟和退出复位条件，I2C4 能访问 0x1a 并读到符合 IMX415 的 ID。不能证明 mode 寄存器已完整配置、Sensor 已开流、CSI-2/D-PHY/RKISP 正常或图像质量正确。</mark>
