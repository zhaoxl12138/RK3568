## 原始代码内嵌中文注释

```c
static const struct of_device_id imx415_of_match[] = {
    { .compatible = "sony,imx415" }, // 驱动声明支持的 OF 匹配标识
    {},                              // C 数组结束哨兵
};

static struct i2c_driver imx415_i2c_driver = {
    .driver = {
        .name = IMX415_NAME,                         // driver 对象名称
        .of_match_table = of_match_ptr(imx415_of_match), // 保存匹配表地址
    },
    .probe = &imx415_probe, // 保存函数地址；此行没有执行 probe
};

static int __init sensor_mod_init(void)
{
    return i2c_add_driver(&imx415_i2c_driver); // 直接调用 I2C 注册宏/函数
}
```

## 调用类型

- `of_match_table = ...`：字段赋值和对象关系。
- `sensor_mod_init()` → `i2c_add_driver()`：直接调用。
- initcall → `sensor_mod_init()`：内核初始化框架回调。
- I2C Core → `imx415_probe()`：匹配后的框架回调。

### C 基础：空结构体哨兵

`{}` 会把成员清零；内核许多匹配表用全零项表示数组结束。`of_match_ptr()` 在启用 OF 时返回表地址，在不启用时可能变为 `NULL`，由编译配置决定。

## 大白话解释

`compatible` 不是驱动的私有密码，也不是内核猜出来的名字；DTS 作者和驱动作者必须遵守同一个 binding 约定。两边字符串相等只说明“软件资料可配对”，真正芯片型号还要在 probe 中通过硬件通信验证。

## 板端证据边界

```bash
cat /sys/bus/i2c/devices/4-001a-1/modalias
cat /sys/bus/i2c/devices/4-001a-1/uevent
readlink -f /sys/bus/i2c/devices/4-001a-1/driver
```

- modalias/compatible：能证明设备携带匹配资料。
- driver 链接：能证明 match 和绑定已完成。
- 不能证明真实硬件一定是 IMX415；该结论需要 ID 读取。

## 面试问题

系统里有很多 Camera driver，I2C Core 怎么“选中” IMX415？

**我的回答：**


<mark>高亮正确答案：参与编译或加载的驱动都会各自注册；I2C Core 对未绑定 client 与 driver 按 OF、ACPI、I2C ID 等规则尝试匹配。当前 client 的 sony,imx415 与 imx415_of_match 相等，因此绑定 imx415_i2c_driver 并回调 imx415_probe。</mark>
