## 代码片段：登记表不是“一次执行全部功能”

```c
static struct i2c_driver imx415_i2c_driver = {
    .driver.of_match_table = imx415_of_match, // 匹配资料
    .probe  = imx415_probe,                   // 函数指针赋值，暂不执行
    .remove = imx415_remove,                  // 解绑时才由框架回调
};

static int __init sensor_mod_init(void)
{
    return i2c_add_driver(&imx415_i2c_driver); // 直接调用：登记驱动
}
```

### 调用类型

- `.probe = imx415_probe`：字段赋值/函数指针。
- `i2c_add_driver(...)`：直接调用。
- `imx415_probe(client, id)`：匹配后 I2C Core 框架回调。
- `imx415->client = client`：对象关系。

### C 基础

`static` 限制符号主要在当前编译单元可见；`__init` 标记初始化函数；`device_initcall_sync()` 用宏把函数指针放入内核启动表。它们不改变 `sensor_mod_init()` 的普通 C 函数体含义。

## 大白话解释

`imx415.c` 像一整套服务手册，里面确实写了 probe、开流、格式和曝光等能力；驱动注册只是把服务目录交给内核，并不会把所有函数执行一遍。具体事件发生时，I2C/V4L2 框架才从对应函数表取出入口回调。

## 板端证据边界

```bash
cat /sys/bus/i2c/devices/4-001a-1/uevent
readlink -f /sys/bus/i2c/devices/4-001a-1/driver
dmesg | grep 'Detected imx415 id'
```

- 能证明：client、绑定以及 probe 读 ID 的层级结果。
- 不能证明：Sensor 已退出 standby 并持续输出 RAW10，也不能证明 D-PHY/ISP 成功接收。

## 面试问题

`sensor_mod_init()` 是否调用了 `imx415_probe()` 和 `imx415_remove()`？

**我的回答：**


<mark>高亮正确答案：没有直接调用。它只调用 i2c_add_driver() 登记 imx415_i2c_driver。匹配成功时 I2C Core 回调 probe；设备解绑或驱动卸载时才回调 remove。</mark>
