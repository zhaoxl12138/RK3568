# 00-03 调试与面试验收：分层证据总表

## Source Insight 定位

当某层证据缺失时，再进入对应源码，不从 `/dev/video0` 盲跳：

| 层 | 文件 | Source Insight 搜索符号 |
|---|---|---|
| 设备发现 | `drivers/of/platform.c` | `of_platform_populate` |
| I2C client | `drivers/i2c/i2c-core-of.c` | `of_i2c_register_devices` |
| Driver Core | `drivers/base/dd.c` | `driver_match_device`、`really_probe` |
| Sensor | `drivers/media/i2c/imx415.c` | `imx415_probe`、`imx415_check_sensor_id` |
| D-PHY/Media | `drivers/phy/rockchip/phy-rockchip-csi2-dphy.c` | `rockchip_csi2dphy_media_init` |
| RKISP/video | `drivers/media/platform/rockchip/isp/dev.c`、`capture.c` | `media_device_register`、`video_register_device` |

E 盘是阅读副本；WSL `/home/rk3568/work/rk3568_linux_sdk/kernel` 是编译事实基线。

## 最小证据梯子

```bash
# 1. 运行时 DTS
tr -d '\0' </sys/firmware/devicetree/base/i2c@fe5d0000/imx415@1a/compatible

# 2. I2C client 与绑定
cat /sys/bus/i2c/devices/4-001a-1/uevent
readlink -f /sys/bus/i2c/devices/4-001a-1/driver

# 3. probe 与芯片通信
dmesg | grep -E 'imx415|csi2-dphy|rkisp'

# 4. 运行时拓扑
media-ctl -p

# 5. video 能力与抓帧
v4l2-ctl -d /dev/video0 --all
v4l2-ctl -d /dev/video0 --stream-mmap=4 --stream-count=30 --stream-to=/tmp/imx415.raw
```

## 证据能证明/不能证明

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| `compatible=sony,imx415` | 运行时 DTB 含该描述 | 真硬件一定是 IMX415 |
| `4-001a-1` | I2C client 已创建 | 0x1a 一定能应答 |
| driver 符号链接 | match 与绑定成功 | probe 全部步骤成功 |
| `Detected ... 0000e0` | 基本上电、时钟、复位、I2C 读 ID 可用 | MIPI、ISP 和出图正常 |
| `[ENABLED]` | entity/pad/link 已建立 | 正在持续传有效帧 |
| 抓到连续且内容正确的帧 | 取流主链工作 | 曝光、色彩和所有模式都已调优 |

## 代码片段：日志是源码里的检查点

```c
ret = imx415_read_reg(client, IMX415_REG_CHIP_ID, 1, &id); // 直接调用 I2C 读取
if (id != CHIP_ID)
    return -ENODEV;                                        // 失败边界

dev_info(dev, "Detected imx415 id %06x\n", CHIP_ID);     // 板端证据来源
```

调用类型：`imx415_read_reg(...)` 是直接调用；进入 `imx415_check_sensor_id()` 本身是 `imx415_probe()` 的直接调用；进入 `imx415_probe()` 则是 I2C Core 的框架回调。

### C 基础：返回值和错误码

内核函数通常用 `0` 表示成功，用负数如 `-ENODEV` 表示失败。调试时既要看日志，也要追 `ret` 从哪里产生、经哪个 `goto` 清理路径返回。

## 大白话解释

排查 Camera 就像逐段验水管：先证明图纸装进系统，再证明阀门对象存在，再证明能和 Sensor 对话，再证明管路拓扑接上，最后才开泵取水。上游某层通过不能替下游作保证。

## 面试问题

板上已经出现 `/dev/video0`，但抓帧超时，你会先改 IMX415 寄存器吗？

**我的回答：**


<mark>高亮正确答案：不会先盲改寄存器。我会依次核对 Sensor ID、media-ctl 的 entity/pad/link 与格式、D-PHY/CSI/RKISP 错误日志，再检查 STREAMON 和缓冲队列。/dev/video0 只证明 video_device 注册，不证明上游正在送帧。</mark>
