# 01-02 对象与数据链：match → really_probe → bus probe

## 通用骨架

```text
driver_match_device(drv, dev)
 └─ drv->bus->match(dev, drv)
      ├─ platform_match()
      └─ i2c_device_match()
           ↓ 成功
driver_probe_device()
 └─ really_probe()
      ├─ I2C：dev->bus->probe(dev)
      │    └─ i2c_device_probe() → i2c_driver.probe(client, id)
      └─ Platform：drv->probe(dev)
           └─ platform_drv_probe() → platform_driver.probe(pdev)
```

## 代码片段：I2C 与 Platform 只是包装不同

```c
struct bus_type i2c_bus_type = {
    .match = i2c_device_match, // 字段赋值：保存 I2C 匹配规则
    .probe = i2c_device_probe, // 字段赋值：保存 I2C probe 包装入口
};

static int i2c_device_probe(struct device *dev)
{
    struct i2c_client *client = i2c_verify_client(dev); // 通用对象转 I2C 对象
    struct i2c_driver *driver = to_i2c_driver(dev->driver);

    return driver->probe(client,
        i2c_match_id(driver->id_table, client)); // 框架回调具体 Sensor probe
}
```

Platform 路径做同一件事，只是包装函数不是放在 `platform_bus_type.probe` 中：`__platform_driver_register()` 会把 `platform_drv_probe` 保存到内嵌的通用 `device_driver.probe`，`really_probe()` 走 `drv->probe(dev)` 后再转换成 `platform_device`，最后回调厂商 `platform_driver.probe(pdev)`。

## 调用类型和对象关系

- `bus_type.match = i2c_device_match`：函数指针字段赋值。
- `driver_match_device()` 调 `drv->bus->match(...)`：框架回调。
- `dev->driver = drv`：保存绑定对象关系。
- `i2c_verify_client(dev)`：直接调用，恢复 I2C 专用对象。
- `driver->probe(client, id)`：I2C Core 对厂商驱动的框架回调。

### C 基础：为什么参数能“变”

`struct i2c_client` 内嵌 `struct device dev`，所以 Driver Core 可以只传通用 `struct device *`。I2C Core 用 `container_of()` 思路从成员地址找回外层 client，这不是复制一个新对象。

## 大白话解释

Driver Core 只会说“设备”和“驱动”这种通用语言；I2C Core 是翻译员，把通用对象还原成 `i2c_client` 与 `i2c_driver`。所以 `imx415_probe()` 的两个参数不是 `sensor_mod_init()` 亲手传的，而是 I2C Core 在最终交接时准备的。

## 板端证据边界

```bash
cat /sys/bus/i2c/devices/4-001a-1/uevent
readlink -f /sys/bus/i2c/devices/4-001a-1/subsystem
readlink -f /sys/bus/i2c/devices/4-001a-1/driver
```

- `subsystem` 指向 i2c：能证明该 device 归属 I2C bus。
- driver 指向 imx415：能证明 I2C match 和绑定完成。
- 不能证明 `imx415_probe()` 中每项资源都成功，也不能证明 MIPI 数据链。

## 面试问题

`struct bus_type i2c_bus_type` 是 I2C client 还是 IMX415 驱动？

**我的回答：**


<mark>高亮正确答案：都不是。它是 I2C 总线框架的规则表，提供 match、probe、remove 等统一入口；i2c_client 和 i2c_driver 都把自己的通用 device/driver 归属到它，再由它负责匹配和参数转换。</mark>
