# 技术流程图绘制规范

## 核心原则

先保证调用关系无歧义，再考虑美观。只要读者能从图中推导出不存在的调用关系，就继续修改图，而不是只在图外补充解释。

## 绘图步骤

1. 先从源码确认每个节点属于哪一类：函数调用、结构体/对象、字段赋值、规则表、状态或判断。
2. 按模块划分泳道，每个节点放进实际负责它的模块。
3. 明确标出起点、独立分支、汇合点和终点。
4. 独立路径左右并列；不要上下排列成伪串行关系。
5. 汇合后按照真实调用顺序绘制一条可连续追踪的串行主链。

## 线条语义

| 线条 | 唯一含义 |
|---|---|
| 实线箭头 | 真实函数调用、控制流或明确的先后执行 |
| 虚线箭头 | 数据依赖、结构体引用、字段归属、共享规则或连接关系 |

- 不要把赋值语句画成函数调用。例如 `driver.bus = &i2c_bus_type` 是字段赋值。
- 不要把对象或规则表画成主动执行步骤。例如 `i2c_bus_type` 是规则表。
- 让每根箭头直接进入自己的目标框；避免箭头从相邻框之间横穿，造成 `A → B` 的错觉。
- 对不明显的虚线标注“数据依赖”“属性关系”“共享规则”等语义。
- “独立、先后不固定”不等于“两个线程同时并行”，除非源码确实创建了并发执行单元。

## 布局规范

- 使用分栏泳道表示 Linux 通用驱动模型、总线 Core、具体驱动等模块边界。
- 独立分支使用对称布局，并分别命名“驱动注册分支”“设备创建分支”等。
- 在汇合框中写清“谁先到谁等待，谁后到谁触发”。
- 在串行主链起点标明“从这里开始串行”。
- 优先制作 HTML + 内联 SVG 大图；按整页宽度展示，使用浏览器缩放，不增加局部缩放按钮和内部滚动框。
- 沿用 Phase0 网页的深色分栏、模块配色和卡片风格。

## 验收清单

交付前逐项回答：

- 从哪里开始？
- 哪些路径独立，哪些步骤串行？
- 每根实线是否能在源码中找到直接调用依据？
- 每根虚线是否明确表达数据、属性或规则关系？
- 是否可能误读出不存在的 `A → B` 调用？
- 宽屏和窄屏是否无裁切、无横向溢出？
- 浏览器控制台是否无错误？

如果任何一项回答不清楚，继续调整节点位置、箭头入口或标签。

## 标准样例

以 `04-项目/16-IMX415-三层驱动调用流程.html` 为本仓库技术流程图的样式与语义基准。

该样例必须保持以下关系清晰：

```text
驱动注册分支 ─┐
              ├→ 设备与驱动到齐 → 串行 match → 串行 probe
设备创建分支 ─┘
```

禁止产生以下误读：

```text
driver.bus → i2c_new_device()
device_register() → driver_register()
```
