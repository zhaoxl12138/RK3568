Media 对象：Entity、Pad、Link

先弄清图里“谁、端口和连接”分别是哪一个 C 对象，再追创建函数。它们描述硬件管线，但不搬运 RAW 像素。

对象关系

内嵌、归属、链表和 reverse，用绿色线。

图 1：四个对象不是四块硬件

struct media_device：根图
struct media_entity：图中的模块
struct media_pad：模块端口
struct media_link：端口之间的软件边
这些对象描述硬件数据通路，但不复制 RAW

图 2：media_entity_pads_init() 只建立归属和下标

调用者先设置 pad Source/Sink flags
media_entity_pads_init()
保存数组、数量、所属 entity 和 index
尚未匹配远端，也未创建 link

图 3：一条逻辑边为何有正向 link 和 backlink

media_create_pad_link()
Source entity 创建正向 link
Sink entity 创建 backlink
两者通过 reverse 互指
只是双向图索引，不是两条物理线

Source Insight

drivers/media/media-entity.c：先看 media_entity_pads_init()，再看 media_create_pad_link() 中正向 link、backlink、reverse 和 flags。

证据边界

entity/pad 出现

证明软件对象已初始化；不能证明远端已经匹配。

link [ENABLED]

证明软件拓扑存在并被选中；不能证明 MIPI 物理信号正常。

连续 DQBUF

才是应用持续拿到真实 buffer 的强证据。
