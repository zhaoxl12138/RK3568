RK3568 D-PHY：从 DTS 到 Media Graph

说明硬件连接

启用 D-PHY，并声明 IMX415 从哪里进入、RKISP 从哪里接走。

创建 D-PHY 对象

通过 compatible 匹配并进入 probe()。

本页名词定位：只讲 D-PHY、CSI-2 与 Media Graph

IMX415 / I2C 的名词在“三层驱动调用流程”页；RKISP / /dev/video0 留到后续 RKISP 章节。

名词本质它什么时候工作在当前 IMX415 项目中的职责
MIPI D-PHYSoC 内部硬件 IP + Platform 驱动开机 probe；开流后持续接收从 4 对 Data Lane 与 1 对 Clock Lane 上可靠接收高速差分电信号，恢复出数据流。
CSI-2MIPI 图像传输协议Sensor 开始发帧时规定 RAW10 数据如何封包、携带帧/行边界与数据类型。它是“规则”，不是一个第三方库。
V4L2 / Media ControllerLinux 内核多媒体框架驱动注册与应用开流时V4L2 提供 subdev、video node、STREAMON 等统一接口；Media Controller 用 entity/pad/link 描述模块怎样相连。
DTS / endpoint启动时载入的硬件配置数据内核启动、驱动 probe 前后status = "okay" 表示启用；endpoint 描述 IMX415 → D-PHY → RKISP 的硬件连接关系。
csi2_dphy0DTS 节点标签内核解析 DTS 时它是“这一个 D-PHY 实例”的设备树名字；不是另一块硬件，也不是驱动函数。&csi2_dphy0 是对该节点继续配置。
platform_device / pdev内核中的设备对象Platform 总线枚举片内硬件时内核把 DTS 的 D-PHY 节点包装成 pdev，再传给 rockchip_csi2_dphy_probe(pdev)。
V4L2 subdev内核中的功能模块对象驱动 probe / 注册时Sensor、D-PHY、CSI、ISP 都可各自注册为 subdev；它不是用户应用直接抓图的 /dev/videoX。
entity / pad / linkMedia Controller 的三种描述对象驱动注册拓扑时entity 是模块，pad 是模块的输入/输出口，link 是两个 pad 的连接；它们让 media-ctl -p 可读。
异步 notifier内核的绑定协调机制各 subdev 注册先后不确定时D-PHY 不要求 IMX415 必须先注册；双方就绪后再根据 endpoint 绑定，避免开机初始化顺序造成失败。
rockchip-csi2-dphy0运行时 Media entity 名称D-PHY 驱动 probe 后它由驱动中的 snprintf() 命名，显示在 media-ctl -p；它对应前面的 D-PHY 硬件实例，不是新硬件。
dmesg / media-ctl用户态诊断工具你主动执行时前者读取内核日志，后者查询 Media Graph；它们只观察和配置，不承担图像处理。
阶段 1 · 编译 / 烧录前

把“说明书”放进系统

DTS 与内核驱动被编译进镜像或做成模块。此时只是准备能力，还没有真正读到 Sensor、更没有图像帧。

阶段 2 · Linux 启动

发现硬件并建立拓扑

Platform 总线创建 D-PHY、RKISP 等片内设备；I2C 创建 IMX415 client。驱动匹配后各自 probe，异步把 entity、pad、link 建起来。先后顺序不必完全固定。

阶段 3 · 应用开流

真正开始传图和处理

应用对 /dev/video0 执行 STREAMON；驱动配置 Sensor 与 RKISP，IMX415 才持续发 MIPI 帧，D-PHY / CSI / ISP 硬件才连续工作。

完整模块流程：先有 DTS，再顺序进入 probe、Media 初始化与异步绑定

1

先读 DTS

先确认这块板是否启用了 D-PHY，以及 IMX415 连到哪个输入端点。

&csi2_dphy0
mipi_in_ucam1 ↔ imx415_out
2

再读 probe

确认它不是 I2C 驱动，而是 RK3568 内部硬件对应的 Platform 驱动。

rockchip_csi2_dphy_probe()
3

读 Media 初始化

理解 Sink/Source pad 是代码创建的；endpoint 是由驱动解析和绑定的。

rockchip_csi2dphy_media_init()
4

回板端验证

把日志和 Graph 当作源码运行后的结果，而不是独立命令输出。

dmesg · media-ctl -p

面试版一句话：我在 RK3568 上通过板级 DTS 启用 csi2_dphy0，用 endpoint 把 IMX415 的 4-Lane 输入和 RKISP 输入连接起来；D-PHY 的 Platform 驱动在 probe 中创建 V4L2 subdev，Media 初始化创建 Sink/Source pad 并异步绑定 Sensor，最终可在 media-ctl -p 中验证 entity、pad 与 Enabled link。
