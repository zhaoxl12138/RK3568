IMX415 v4l2_subdev：从注册到开流

先按职责整理 imx415.c：谁注册驱动、谁执行 probe、谁注册 V4L2 subdev、谁负责格式、曝光和开流。内部宏和 I2C 字节细节暂时不追。

从关键函数地图开始← 返回 Camera 真实启动主线前置：I2C 匹配与 probe后续：D-PHY 与 Media Graph →打开第 1 章笔记

先看这里：三个“注册”不要混

注册 1 · I2C 驱动

sensor_mod_init()

调用 i2c_add_driver(&imx415_i2c_driver)，把整套 IMX415 驱动交给 I2C Core。设备匹配成功后，系统才会回调 imx415_probe()。

注册 2 · V4L2 操作能力

v4l2_i2c_subdev_init()

把 i2c_client、v4l2_subdev 和 imx415_subdev_ops 关联起来。它不是注册 I2C 驱动。

注册 3 · Camera 子设备

v4l2_async_register_subdev_sensor_common()

把 IMX415 作为 Sensor subdev 加入 V4L2 异步框架，之后才能与 D-PHY、CSI 和 RKISP 完成绑定。

中心主题IMX415 驱动生命周期注册驱动 → 匹配并初始化 → 加入 Camera 框架 → 响应运行期操作
分支 1

驱动注册

  1. sensor_mod_init()模块初始化入口
  2. i2c_add_driver()把驱动交给 I2C Core
  3. imx415_i2c_driver结构体保存 match / probe / remove
分支 2

匹配与 probe

  1. .probe = imx415_probecompatible 匹配成功后由 I2C Core 回调
  2. imx415_probe()获取 DTS 资源、初始化 controls 和软件对象
  3. __imx415_power_on()执行 GPIO、RESET、xvclk 上电时序
  4. imx415_check_sensor_id()I2C 读取并确认芯片 ID
分支 3

V4L2 / Media 注册

  1. v4l2_i2c_subdev_init()关联 client、subdev 与 subdev_ops
  2. media_entity_pads_init()建立 IMX415 的 Source Pad
  3. v4l2_async_register_subdev_sensor_common()注册 Sensor subdev，等待管线绑定
分支 4

运行期控制与开流

  1. imx415_pad_ops回调到 imx415_set_fmt()：选择输出模式
  2. imx415_ctrl_ops回调到 imx415_set_ctrl()：曝光、增益、VBLANK
  3. imx415_video_ops回调到 imx415_s_stream()：接收开流/停流请求
  4. __imx415_start_stream()写模式寄存器并退出 Standby，输出 RAW10

重点：对外入口与内部函数

LINUX I2C / PM 框架

I2C Driver 入口

  • imx415_probe()：匹配成功后的初始化入口
  • imx415_remove()：设备移除时的清理入口
  • imx415_pm_ops：运行时电源管理入口
V4L2 CAMERA 框架

V4L2 subdev_ops

  • imx415_set_fmt()：选择输出模式
  • imx415_s_stream()：开流与停流
  • imx415_get_fmt()：读取当前格式
V4L2 CONTROL 框架

V4L2 ctrl_ops

  • imx415_set_ctrl()：统一处理曝光、增益、VBLANK 等控制请求
内部函数不需要注册

这些入口被框架调用后，再继续调用 __imx415_power_on()、imx415_check_sensor_id()、imx415_read_reg()、imx415_write_reg()、__imx415_start_stream() 等内部实现。

需要按函数名查询时，展开完整函数速查表
代码名角色现在要记住什么
sensor_mod_init()驱动注册入口调用 i2c_add_driver()；它不直接调用 imx415_probe()。
imx415_i2c_driver驱动描述结构体它不是函数；其中声明匹配表、probe、remove 和电源管理入口。
imx415_probe()初始化总入口匹配成功后由 I2C Core 调用；负责资源获取、控制项、上电、读 ID、subdev 和 Media 注册。
__imx415_power_on()上电时序处理电源 GPIO、RESET 和 xvclk，让 Sensor 进入可通信状态。
imx415_check_sensor_id()芯片确认通过 I2C 读取并比较 Sensor ID；成功只能证明控制通道和基本上电可用。
v4l2_i2c_subdev_init()关联 V4L2 能力把 client、subdev 与 imx415_subdev_ops 绑定起来。
media_entity_pads_init()建立数据端口初始化 IMX415 唯一的 Source Pad，表示 RAW 图像从 Sensor 输出。
v4l2_async_register_subdev_sensor_common()注册 Sensor subdev将 IMX415 放入异步匹配体系，等待 Camera 管线完成绑定。
imx415_set_fmt()选择输出模式根据分辨率、格式等选择并保存当前 Sensor mode。
imx415_set_ctrl()设置控制参数处理曝光、增益、VBLANK 等控制项，并在合适时机写入 Sensor 寄存器。
imx415_s_stream()开流/停流入口接收 V4L2 的开流请求；开流时调用 __imx415_start_stream()。
__imx415_start_stream()真正启动 Sensor写全局和模式寄存器表、应用 controls，最后退出 Standby，开始输出 RAW10。

推荐代码阅读顺序

1. 驱动入口sensor_mod_init() → imx415_i2c_driver
2. probe 骨架先看 imx415_probe() 的大步骤，不钻辅助函数。
3. 上电与识别__imx415_power_on() → imx415_check_sensor_id()
4. 加入 Camera 框架subdev → Source Pad → async register
5. 运行期操作set_fmt() → set_ctrl() → s_stream()

只需理解职责

imx415_subdev_ops、imx415_video_ops、imx415_pad_ops 是“函数入口表”，框架通过它们找到具体回调。

暂时不追

to_imx415/container_of、i2c_transfer 字节细节、pm_runtime 内部实现，以及 V4L2 宏展开。

理解这些函数前，先记住四个概念

概念 1

subdev 是软件对象

它不是硬件模块，也不是第三方库，而是 Linux V4L2 框架描述 Camera 子设备的内核对象。

概念 2

I2C 身份不会消失

i2c_client 继续保存 I2C4、地址 0x1a 和 DTS 节点；subdev 只是在它上面增加 Camera 能力。

概念 3

Pad 描述数据方向

IMX415 只有一个图像输出端，所以 pad0 是 Source，并通过 endpoint 连接 D-PHY 的 Sink。

概念 4

STREAMON 才调用开流

注册阶段建立对象和链路；应用执行 STREAMON 后，才进入 imx415_s_stream(1) 输出 RAW10。

补充概念：同一颗 IMX415 的三个软件身份

I2C CORE

struct i2c_client

保存 adapter=I2C4、addr=0x1a、dev.of_node=imx415@1a。解决“如何找到并通过 I2C 控制 Sensor”。

V4L2

struct v4l2_subdev

保存标准 subdev 身份和操作表入口；具体的 cur_mode、streaming、ctrl_handler 等状态主要保存在 struct imx415 中。

MEDIA CONTROLLER

media_entity + media_pad

声明它是 Camera Sensor，并有一个 Source Pad。解决“IMX415 在图像拓扑中的位置以及数据流向哪里”。

核心关系：v4l2_i2c_subdev_init() 不是删除 i2c_client，而是把同一颗 IMX415 的 I2C 身份、V4L2 身份和操作函数关联起来。

SUBDEV 证据

/dev/v4l-subdev3

对应 m00_b_imx415 4-001a-1。它代表 Sensor 子设备身份，主要用于控制和拓扑，不承载应用取出的完整帧。

MEDIA 证据

pad0: Source

media-ctl -p 显示 IMX415 的 RAW10 格式及到 rockchip-csi2-dphy0 的 ENABLED Link。

VIDEO 证据

/dev/video0

这是 RKISP mainpath 的帧数据节点。只有 STREAMON、抓帧成功且没有 CSI/MIPI 错误，才能证明完整出图链路工作。

一句话复述：IMX415 驱动先通过 v4l2_i2c_subdev_init() 把 I2C client 包装成 V4L2 Sensor subdev，再通过 Media Entity、Source Pad 和异步注册加入 Camera 拓扑；应用对 RKISP 的 /dev/video0 执行 STREAMON 后，框架沿 Pipeline 调用 imx415_s_stream(1)，Sensor 才开始输出 RAW10。

排障边界：读 ID 成功只证明 I2C 控制通道和基本上电正常；存在 /dev/v4l-subdev3 只证明 Sensor 已注册；Media Link 为 ENABLED 只证明拓扑建立。真正出图仍需要格式一致、D-PHY/CSI/RKISP 正常和抓帧成功。
