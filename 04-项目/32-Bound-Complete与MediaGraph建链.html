阶段 06 · 专题 3/3

Bound / Complete 与分段建链

D-PHY 的 bound 是“一个局部上游到位”；RKISP 的 complete 是“整棵依赖树收口”。两者都由 Async 回调，但职责和调用次数不同。

图 1 · 中间桥D-PHY 为什么同时有 notifier 和 sd图 2 · 局部建链Sensor→D-PHY 在 bound 中创建图 3 · 全局收口RKISP complete 创建剩余 links

直接调用

回调函数内部主动调用建链 API。

框架回调

Async Core 根据 fwnode 命中后调用 bound/complete。

对象关系 / 数据流

notifier 向上等待，sd 向下被匹配；RAW 方向另行标注。

图 1：D-PHY 同时是下游接收者和上游提供者

IMX415 subdev 独立注册
dphy->notifier 向上匹配 Sensor
dphy->sd 表示 D-PHY 自己
RKISP notifier 再向下匹配 D-PHY sd
这是两次 Async 匹配，不是一次匹配跨三方

图 2：D-PHY bound 完成局部 Sensor→D-PHY 建链

Async fwnode 匹配命中真实 Sensor
rockchip_csi2_dphy_notifier_bound()
保存 sd / lanes / mbus，并查 Source pad
media_create_pad_link()
建立 Sensor→D-PHY 局部软件 link

图 3：RKISP complete 是整棵 Camera 依赖树的收口

根 notifier 及子 notifier 全部 ready
subdev_notifier_complete()
rkisp_create_links()
media-ctl -p 可见完整软件拓扑
仍需 STREAMON、IRQ、DMA、DQBUF 才能证明真实帧

Source Insight

D-PHY：phy-rockchip-csi2-dphy.c → rockchip_csi2_dphy_notifier_bound()；RKISP：dev.c → subdev_notifier_complete() → rkisp_create_links()。

一句面试表达

V4L2 Async 解决独立 probe 对象的到达顺序问题：D-PHY notifier 匹配 Sensor 后在 bound 中完成局部 Sensor→D-PHY link；D-PHY 自己的 sd 再被 RKISP 根 notifier 匹配，整棵依赖树 ready 后由 complete 统一创建剩余 links。Media Graph 完整仍只证明软件拓扑，不等于已经出帧。
