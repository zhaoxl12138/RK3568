3. 各子系统深度拆解

段 A：Camera → /dev/video0

阶段2只记一句：MIPI 屏上的官方 Camera 应用能出图，只能说明官方应用链路可跑；你能用 v4l2-ctl 从 /dev/video0 抓到帧，才说明用户态可控采集链路打通。
核心问题：Camera 数据从 MIPI 口进来后，Linux 怎么把它变成 /dev/video0？
传感器驱动IMX415 (drivers/media/i2c/imx415.c) — v4l2_subdev，配置曝光/增益/帧率，输出 RAW Bayer
CSI Host 驱动drivers/media/platform/rockchip/csi/ — MIPI CSI-2 RX 控制器，接收 4-lane CSI-2 数据
ISP 驱动drivers/media/platform/rockchip/isp/ — rkisp_mainpath (主输出 NV12)、rkisp_selfpath (第二路)、rkisp-statistics (3A 统计)、rkisp-input-params (3A 参数)
Media Controller/dev/media0 — 描述 imx415 → csi2_rx → rkisp_input → rkisp_mainpath → video0 的拓扑 entity/pad/link
VB2 缓冲区videobuf2-dma-contig (DMA 连续内存) — mmap 模式 3 缓冲区
用户态接口/dev/video0 — ioctl(VIDIOC_QUERYCAP/S_FMT/REQBUFS/QBUF/DQBUF/STREAMON)
# 列出所有 video 节点 v4l2-ctl --list-devices # rkisp_mainpath (platform:rkisp0): # /dev/video0 # /dev/video-camera0 ← 字符链接 # /dev/media0 ← Media Controller # 查看当前格式 v4l2-ctl -d /dev/video0 --all # Format: NV12 1280×720 # 单帧大小: 1,382,400 bytes
# 抓取一帧验证 v4l2-ctl -d /dev/video0 \ --set-fmt-video=width=1280,height=720,pixelformat=NV12 \ --stream-mmap=3 \ --stream-count=1 \ --stream-to=/tmp/frame.yuv

段 B：GStreamer → OpenCV

阶段4只记一句：OpenCV 在这里不是直接碰 Camera 驱动，而是从 GStreamer 的 appsink 出口取到已经转换好的 BGR 帧。
核心问题：为什么 cv2.VideoCapture(0) 直接打开失败？
失败原因RKISP 输出是 V4L2 multiplanar (mplane) 设备；OpenCV 默认 V4L2 后端不能稳健处理 mplane 节点；默认 GStreamer 后端不自动生成正确 pipeline
解决方案显式构造 GStreamer pipeline 字符串，传入 cv2.VideoCapture(pipeline, cv2.CAP_GSTREAMER)
v4l2srcGStreamer V4L2 source element — 从 /dev/video0 读帧，内部用 ioctl QBUF/DQBUF
格式协商video/x-raw,format=NV12,width=1280,height=720 — Caps filter 指定输入格式
videoconvertGStreamer 色彩空间转换 element — NV12 (YUV 4:2:0) → BGR (OpenCV 原生格式)
appsinkGStreamer AppSink element — drop=1 (满队列丢帧) / sync=false (不等时钟) — 将 GstBuffer 传到 Python 层
import cv2 # 成功：显式 GStreamer pipeline pipeline = ( 'v4l2src device=/dev/video0 ' '! video/x-raw,format=NV12,width=1280,height=720 ' '! videoconvert ' '! video/x-raw,format=BGR ' '! appsink drop=1 sync=false' ) cap = cv2.VideoCapture(pipeline, cv2.CAP_GSTREAMER) ret, frame = cap.read() # frame.shape = (720, 1280, 3) ← BGR uint8 # 失败：OpenCV 直接打开 # cap = cv2.VideoCapture(0) ← 报错: can't open camera # cap = cv2.VideoCapture(0, cv2.CAP_V4L2) ← 同样失败

段 C：OpenCV → RKNN → NPU

阶段5只记一句：Python 代码只是调度者，真正干 AI 推理的是 RKNN Runtime 下面的 NPU。
核心问题：AI 推理到底在哪个硬件上怎么跑的？模型文件是什么格式？
NPU 硬件RK3568 内置 NPU，1.0 TOPS，通过内核驱动 v0.8.2 暴露
NPU 驱动CONFIG_ROCKCHIP_NPU — /dev/rknpu (或类似设备节点)
RKNN Runtimelibrknnrt.so v1.5.0 — 用户态运行时库，封装 NPU ioctl 调用
rknn_server/usr/bin/rknn_server — 板端守护进程，管理 NPU 资源分配
rknn-toolkit-lite2Python wheel 1.5.0 — RKNNLite 类封装 load_rknn / init_runtime / inference / release
模型文件yolov5s_relu_tk2_RK356X_i8.rknn — 预编译 INT8 量化 RKNN 模型 (针对 RK356X)
输出张量3 个分支: (1,255,80,80) stride=8 / (1,255,40,40) stride=16 / (1,255,20,20) stride=32
from rknnlite.api import RKNNLite # 1. 创建 RKNN 对象 rknn = RKNNLite() # 2. 加载预编译 RKNN 模型 rknn.load_rknn('yolov5s_relu_tk2_RK356X_i8.rknn') # 3. 初始化 NPU 运行时 rknn.init_runtime() # 4. 前处理: BGR→RGB, letterbox→640×640, normalize input_data = preprocess(frame) # → (1, 3, 640, 640) float32 # 5. NPU 推理 outputs = rknn.inference(inputs=[input_data]) # outputs[0].shape = (1, 255, 80, 80) # outputs[1].shape = (1, 255, 40, 40) # outputs[2].shape = (1, 255, 20, 20) # 6. 后处理: 解码框 + NMS boxes = postprocess(outputs) # 7. 释放 rknn.release()

段 D：后处理 → 显示 + 推流

阶段7和阶段8只记一句：画框、旋转、MIPI 显示、FFmpeg 编码、HLS 推流，都是推理之后的输出链路，不属于 NPU 本体。
核心问题：检测结果怎么同时显示在板端屏幕和推给 Windows？
后处理解码 3 个 RKNN 输出 → Sigmoid → 置信度过滤 → NMS → 坐标映射回原图 → cv2.rectangle 画框 → cv2.putText 标签
MIPI 显示cv2.imshow() → OpenCV HighGUI → DRM/KMS (/dev/dri/card0) → dw-mipi-dsi → LCD，~4 FPS
方向独立控制ROTATE=none (模型输入) / DISPLAY_ROTATE=ccw (MIPI 屏) / STREAM_ROTATE=ccw (HLS 推流)，三者独立
FFmpeg 推流Python cv2.imencode('.jpg') → pipe → FFmpeg stdin → libx264 编码 → FLV 封装 → RTMP → nginx
Nginx 配置rtmp { listen 1935; application live { hls on; hls_path /tmp/hls; } } — 切片生成 .m3u8 + .ts
Windows 拉流ffplay http://192.168.0.230/hls/yolo.m3u8 — ~5 FPS
为什么不用纯 GStreamer RTMP板端 GStreamer 有 rtmpsink 但缺少 flvmux 插件
# 板端：一键启动完整演示 (MIPI + HLS) cd /userdata/aidemo/06_yolov5_python SHOW_MIPI=1 FRAMES=0 ./start_yolov5_hls_demo.sh # Windows：拉流 ffplay http://192.168.0.230/hls/yolo.m3u8 # 方向独立控制示例 ROTATE=none DISPLAY_ROTATE=ccw STREAM_ROTATE=ccw \ ./start_yolov5_hls_demo.sh
