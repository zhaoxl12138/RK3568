阶段 07 · 专题 2/3

内部节点注册与外部 Async 建链

RKISP 先创建自身的 ISP、CSI、stream 等内部对象；Sensor 和 D-PHY 则独立 probe，随后通过 V4L2 Async 到齐。两个“汇合点”不是一回事。

先分清三个名词

rkisp_device 是一套逻辑管线总对象；ISP/CSI 是加入 Media Graph 的 v4l2_subdev；mainpath/selfpath 是面向应用的 stream/video node。三者不能统称为同一种“节点”。

外部 Media Graph 完整

内部汇合

rkisp_register_platform_subdevs() 创建 RKISP 自己拥有的 ISP、CSI、stream 对象。

外部汇合

subdev_notifier_complete() 等 Sensor、D-PHY 等独立对象到齐，再建外部 link。

为什么 videoX 可先出现？

Video Node 在内部 stream 注册阶段即可发布；外部 Async complete 可能尚未发生。

Source Insight 只追三组

dev.c

rkisp_register_platform_subdevs()：看内部对象注册顺序与错误回退。

capture.c / capture_v21.c

rkisp_register_stream_vdevs() → rkisp_register_stream_v21() → rkisp_register_stream_vdev()。

dev.c Async 回调

subdev_notifier_complete()、rkisp_create_links()：看外部对象到齐后的建链。

证据边界

/dev/videoX 存在

证明一个 video_device 已发布；不能证明外部 Media Links 完整。

Async complete 日志

证明软件匹配和建链流程走到 complete；不能证明 MIPI 物理信号或真实帧。

media-ctl -p link ENABLED

证明软件拓扑和启用状态；下一页继续追 STREAMON 与中断。
