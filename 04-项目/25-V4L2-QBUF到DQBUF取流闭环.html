阶段 08 · 专题 2/3

QBUF → STREAMON → IRQ → DQBUF

上半程追“启动命令怎样进入驱动”，下半程追“真实图像怎样写满 Buffer 并返回应用”。两条线合起来才是取流闭环。

图 1 · 应用循环先交空 Buffer，再开流，再不断取回和归还 图 2 · STREAMON 控制流V4L2/VB2 怎样回调 RKISP 与上游 subdev 图 3 · 帧完成数据流DMA、IRQ、DONE、DQBUF 怎样闭环

直接调用

函数体里明确写出的普通调用，用灰蓝实线表示。

框架回调

VB2 查 q→ops、RKISP 查 pipe.set_stream 后调用，用紫色虚线表示。

数据流 / Buffer 所有权

绿色线表示 RAW 帧写入和 Buffer 返回应用，不是假装成函数调用。

图 1：应用先交 Buffer，再循环取回

直接调用框架回调Buffer 所有权
① queue_all_buffers()：把所有空 Buffer QBUF 给驱动
② start_streaming()：发送 VIDIOC_STREAMON
③ capture_frames()：poll() 等待帧完成
④ VIDIOC_DQBUF 取回 DONE Buffer，处理后再次 QBUF

图 2：STREAMON 怎样逐层启动 RKISP 和上游

先记主链：V4L2 Core 分发命令，VB2 管队列状态，RKISP 启动采集硬件，pipeline 回调再让 ISP、CSI、D-PHY、Sensor 开流。

video_ioctl2()：识别 STREAMON
vb2_ioctl_streamon() → vb2_core_streamon()
q→ops→start_streaming 回调 rkisp_start_streaming()
rkisp_stream_start()：配置 MI / DMA
rkisp_pipeline_set_stream()：通知上游 s_stream(1)

图 3：真实一帧怎样从硬件回到 DQBUF

RAW 经 ISP，MI / DMA 写入 ACTIVE Buffer
rkisp_mi_v21_isr()：收到 frame-end IRQ
mi_frame_end() → vb2_buffer_done(DONE)
vb2_core_dqbuf() 从 done_list 取出并返回应用

最重要的证据边界

STREAMON 返回 0

只能证明启动调用链没有立即报错，不能证明已经收到一帧。

一次 DQBUF 成功

证明至少有一个 Buffer 被硬件写完并交回应用。

连续 DQBUF + sequence 连续

才是稳定取流的更强证据；专题 3 用 100 帧数据完成验证。
