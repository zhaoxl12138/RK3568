Linux 设备模型：Camera 总线分层

先分清“谁管理谁”：SoC 内部控制器通常走 Platform Driver，挂在控制器上的外设走各自的总线 Driver，Camera 功能再接入 V4L2 与 Media Controller。

返回学习驾驶舱主线：从 DTS 到 videoX进入 IMX415 / I2C进入 V4L2 subdev进入 D-PHY / Media Graph
第一层 · Linux 基础模型

bus / device / driver

内核的通用管理者，负责把设备和驱动放到对应总线，再安排匹配与 probe。

第二层 · SoC 内部控制器

Platform Driver

管理固定集成在 RK3568 内部、具有寄存器地址、时钟、复位和中断的硬件。

第三层 · 控制器下的外设

I2C / SPI / USB Driver

外设通过哪条公共总线连接，就由哪套总线模型完成匹配和访问。

第四层 · Camera 功能框架

V4L2 / Media Controller

把 Sensor、D-PHY、CSI、ISP 组织成 Camera 的功能链路。

套到你的 RK3568：控制器和外设不是同一个 Driver

名词放回它所属的层

名词属于哪一层大白话解释在你的板子上
Platform Driver总线模型驱动 SoC 内部固定集成的控制器或功能 IP。RK3568 I2C 控制器、D-PHY、CSI、ISP 等。
I2C Driver外设总线模型驱动挂在 I2C 总线上的具体外设。IMX415 的 imx415_i2c_driver。
I2C CoreLinux 内核子系统创建 client，并提供 I2C 的 match、probe、remove 交接规则。把 4-001a 交给 IMX415 驱动。
CSI-2 / D-PHY / ISP硬件功能或协议CSI-2 是传输规则；D-PHY 是物理接收；ISP 是图像处理硬件。它们通常由 Platform Driver 初始化，再接入 V4L2/Media。
V4L2 / Media ControllerCamera 功能框架V4L2 提供统一视频接口；Media Controller 描述 entity、pad、link 的连接。IMX415、D-PHY、CSI、ISP 组成可查询的 Media Graph。
DTS硬件配置数据告诉内核有哪些设备、资源和连接，不是驱动代码。i2c@fe5d0000、imx415@1a、endpoint。

开机与出图是两个阶段

阶段 1 · Linux 启动

把对象和拓扑建起来

DTS 被解析；Platform 控制器和 I2C 外设分别创建对象；驱动匹配并执行 probe；V4L2/Media 注册 subdev、entity、pad、link。

阶段 2 · 应用开流

硬件才开始连续传帧

应用对视频节点执行 STREAMON 后，驱动配置 Sensor 和 ISP，IMX415 才持续发送 MIPI 图像数据。

面试记忆

不要混淆初始化与传输

probe 证明设备和驱动接上了；STREAMON 才证明系统开始请求连续图像。

一句话：SoC 内部控制器通常走 Platform Driver；控制器下面的外设走对应总线 Driver；Camera 再通过 V4L2 和 Media Controller 组织成图像链路。
