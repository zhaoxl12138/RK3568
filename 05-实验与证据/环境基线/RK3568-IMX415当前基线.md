# RK3568 + IMX415 环境基线

“当前”只表示这份基线最后整理时能从仓库记录审计到的状态，不表示设备重启、换网或换固件后仍然不变。

结论：`4.19.232` 是 2026-07-28 板端运行内核记录；`4.19.255` 目前只是未核实的 Media API 版本线索。两者不是可互换字段。

## 格式层级

| 名称 | 所在层级 | 本基线的解释 |
|---|---|---|
| `SGBRG10_1X10` | Sensor / subdev Media bus | IMX415 RAW10 Bayer 在 pad/link 上的总线表示 |
| `YUYV8_2X8` | ISP source pad 一侧的 Media bus format | 描述 subdev pad 之间的总线格式；仓库未保留带日期的完整原始输出，因此不把它绑定为 2026-07-28 的永久“当前格式” |
| `NV12` | `/dev/video0` video node memory format | 描述用户态缓冲区中的 YUV 4:2:0 多平面布局；它不能替代 Media bus format |

因此，看到 `YUYV8_2X8` 与 `NV12` 并不构成冲突：前者是 Media bus / pad 层，后者是 video node memory / buffer 层。任何页面写“当前格式”时必须同时写日期、节点和命令。

## Video 节点映射

| 节点 | 2026-07-28 记录的角色 | 可否作为普通图像采集节点 |
|---|---|---|
| `/dev/video0` | `rkisp_mainpath` | 是，需再核对协商格式与取流结果 |
| `/dev/video7` | `rkisp-statistics` | 否；承载 ISP 3A statistics 元数据 |
| `/dev/video8` | `rkisp-input-params` | 否；承载 ISP input-params 元数据 |

旧文档把 `/dev/video7`、`/dev/video8` 都写成 statistics 的表述已被 `EVID-20260728-CAMERA-DAY1` supersede。

## 分辨率状态

| 分辨率 | 日期 / 命令上下文 | 状态分类 | 审计边界 |
|---|---|---|---|
| `1280×720` | 2026-05-28 `v4l2-ctl -d /dev/video0 --all` 记录为查询时值；随后又由 `--set-fmt-video` 显式请求并抓取 1 帧/30 帧 | 当次查询状态 + 协商后的实验配置 | 不是 2026-07-28 的默认值；原始 `.yuv` 未纳入本证据目录 |
| `1920×1080` | 2026-05-28 通过 `--set-fmt-video` 显式请求单帧 | 协商后的实验配置 | 不是默认当前配置 |
| `3840×2160` | 2026-07-28 `v4l2-ctl --all` / `media-ctl -p` 摘录中的 video node 查询值与 crop | 当次查询状态 | 不能外推为每次启动的默认配置，也不能单凭查询证明已抓帧 |

## 命令基线

Buildroot 板端使用现有 BusyBox / 工具链提供的命令。文本检索写 `grep`，不默认安装 `rg`。IP、节点、分辨率和格式都要在命令中显式记录，避免后续同名“当前状态”覆盖历史环境。
