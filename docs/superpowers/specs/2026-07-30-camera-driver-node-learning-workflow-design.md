# Camera 驱动节点式学习与 HTML 发布工作流设计

## 1. 目标

把 `04-项目/14-Phase0-驱动层全链路框架图.html` 作为 Camera 驱动学习地图，但不提前为所有节点生成空白或半成品网页。

每次只学习一个节点。学习过程保存在对应 Markdown 章节中；完成原理、源码、板端证据和面试表达验收后，才生成正式 HTML，并在框架图对应节点下增加跳转按钮。

核心原则：

```text
框架图选定节点
→ 学习与问答
→ 源码和板端验证
→ 章节验收
→ 整理 Markdown
→ 生成 HTML
→ 框架图增加入口
→ 进入下一节点
```

## 2. 页面与文档职责

### 2.1 Phase0 驱动层全链路框架图

职责：

- 展示完整数据链路和节点之间的关系。
- 标明当前学习节点。
- 为已经完成的章节提供“进入学习”按钮。
- 提供上一节点、当前节点和下一节点的顺序。

不负责：

- 保存完整源码分析。
- 保存学习问答和错误答案。
- 展示尚未完成章节的长篇内容。

### 2.2 Markdown 学习章节

职责：

- 作为章节唯一可编辑知识源。
- 保存用户原始回答。
- 在错误或不完整答案下面保存高亮正确答案。
- 保存原理图、DTS、内核源码和板端命令证据。
- 保存尚未解决的问题和章节验收状态。

学习过程中只维护 Markdown，不要求同步生成正式 HTML。

### 2.3 正式 HTML 章节

职责：

- 展示已经完成并通过验收的章节。
- 提供适合连续阅读的结构、图片、代码和流程图。
- 提供“上一节点 / 返回全链路图 / 下一节点”导航。
- 作为复习、面试准备和项目展示页面。

HTML 是章节完成后的发布产物，不是学习草稿。

## 3. Camera 驱动学习章节

第一轮只覆盖 Camera 到 `/dev/video0`，不扩展到 OpenCV、RKNN、显示和推流。

| 顺序 | 学习节点 | 章节 | 状态 |
| --- | --- | --- | --- |
| 1 | IMX415 Sensor 与驱动 | `RK3568-IMX415-SDK源码对照` | 已完成并已有 HTML |
| 2 | MIPI D-PHY 与 CSI-2 | `RK3568-MIPI-DPHY-CSI2源码对照` | 下一章 |
| 3 | RKISP | `RK3568-RKISP源码对照` | 未开始 |
| 4 | Media Controller | `RK3568-Media-Controller源码对照` | 未开始 |
| 5 | V4L2、VB2 与 mainpath | `RK3568-V4L2-VB2-dev-video0源码对照` | 未开始 |

章节按可独立学习和验收的模块划分，不机械对应框架图中的每一个视觉小方框。

## 4. 单章固定结构

每个章节使用以下结构：

1. 本节点解决什么问题。
2. 上一节点输入什么，本节点输出什么。
3. 对应的硬件模块和原理图信号。
4. 对应的 DTS 节点、属性和 endpoint。
5. 对应的内核配置、源码目录和驱动对象。
6. 关键结构体和函数调用关系。
7. 在 `dmesg`、sysfs、`media-ctl` 或 `v4l2-ctl` 中如何观察。
8. 板端最小实验与可保存证据。
9. 常见故障、现象和第一检查点。
10. 用户原始回答与高亮正确答案。
11. 面试表达。
12. 章节验收结果。

## 5. 问答记录规则

用户回答后：

- 原始答案必须保留，不替换。
- 正确答案紧跟在原始答案下面。
- 错误答案使用醒目标记说明问题所在。
- 不完整但方向正确的答案，需要指出“正确部分”和“缺少部分”。
- 每轮只引入当前节点所必需的新概念，避免同时跳到下游模块。

推荐格式：

```markdown
### 问题

我的回答：……

> [!success] 正确答案
> ……

> [!warning] 需要修正
> ……
```

## 6. 章节完成条件

只有同时满足以下条件，章节才可以生成正式 HTML：

- 能用自己的话解释节点职责和边界。
- 能解释与上一节点、下一节点的接口。
- 能在原理图或芯片框图中找到关键连接。
- 能找到对应 DTS 配置。
- 能找到对应内核源码入口和关键函数。
- 能从板端输出中找到该节点的运行证据。
- 能说明至少三个常见故障的第一检查点。
- 能完成本章验收问题。
- 能形成一段不依赖笔记的面试表达。

“系统能够出图”只能作为运行证据之一，不能替代原理和源码验收。

## 7. HTML 发布规则

章节通过验收后：

1. 清理 Markdown 中的临时讨论和重复内容。
2. 保留原理、源码、证据、排障和面试表达。
3. 由现有网页生成器生成对应 HTML。
4. 检查图片、源码链接、中文编码和移动端布局。
5. 在框架图对应节点下增加“进入学习：章节名”按钮。
6. 在章节 HTML 中增加上一节点、返回框架图和下一节点入口。
7. 更新章节状态为“已完成”。

未完成的节点可以显示“学习中”或“未开始”，但不链接空白 HTML。

## 8. 第二章范围

下一章为“MIPI D-PHY 与 CSI-2”，学习范围固定为：

- 单条 Lane 的串行传输与多 Lane 并行工作。
- Clock Lane、Data Lane 和 P/N 差分信号。
- IMX415 四 Lane 原理图连接。
- `data-lanes = <1 2 3 4>`。
- D-PHY 与 CSI-2 Receiver 的职责边界。
- CSI-2 数据包、帧起止、Data Type 和 Virtual Channel 的基础概念。
- Sensor endpoint 与 D-PHY endpoint。
- `rockchip-csi2-dphy0`、`rkisp-csi-subdev` 在 Media Graph 中的位置。
- 相关 DTS、驱动源码和板端证据。
- Lane、时钟和 endpoint 错误时的典型现象。

本章暂不展开 RKISP 内部图像处理、VB2 缓冲区、OpenCV、RKNN、显示和推流。

## 9. 成功标准

工作流成功的标志：

- 任意时刻只有一个当前学习章节。
- 用户能从框架图知道自己在数据链路中的位置。
- 正式 HTML 只包含已经理解和验收的内容。
- 新章节不会重复已有笔记。
- 完成五章后，用户能够从 Sensor 一直追踪到 `/dev/video0`，并能结合原理图、DTS、源码和板端输出解释全链路。
