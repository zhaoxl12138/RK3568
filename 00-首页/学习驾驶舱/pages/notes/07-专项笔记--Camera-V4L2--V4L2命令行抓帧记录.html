V4L2 是什么

V4L2 全称是 Video4Linux2，是 Linux 下访问摄像头、采集卡、视频输入设备的标准接口。

可以把它理解为 Linux 给应用程序提供的一套 Camera API。应用程序不用直接操作 MIPI、ISP、Sensor 寄存器，而是通过 /dev/videoX 这样的设备节点拿图像。

常见关系：

Sensor / MIPI / ISP 驱动
-> Linux 内核 V4L2 框架
-> /dev/video0
-> 用户态程序读取帧

我后面写 C++ 程序时，本质上也是通过 V4L2 或封装了 V4L2 的库去拿帧。

v4l2-ctl 是什么

v4l2-ctl 是一个命令行测试工具，用来查看和控制 V4L2 设备。

它可以做这些事：

  • 查看有哪些摄像头节点
  • 查看节点支持什么格式和分辨率
  • 设置分辨率、像素格式
  • 直接抓帧到文件
  • 查看曝光、增益、翻转等控制项

它不是最终项目程序，但很适合做底层验证。

当前识别到的节点

命令：

v4l2-ctl --list-devices

关键结果：

rkisp_mainpath:
  /dev/video0
  /dev/video-camera0

rkisp_selfpath:
  /dev/video1

rkisp raw/stat/params:
  /dev/video2 ~ /dev/video8

当前最重要的节点：

/dev/video0

它是 rkisp_mainpath，也就是主采集通道。

/dev/video-camera0 和 /dev/video0 指向同一个主采集能力，可以理解为便捷入口。

当前默认图像格式

命令：

v4l2-ctl -d /dev/video0 --all

关键结果：

Width/Height : 1280/720
Pixel Format : NV12
Size Image   : 1382400

含义：

  • 当前输出分辨率是 1280x720
  • 当前像素格式是 NV12
  • 一帧大小是 1382400 字节

计算方式：

1280 * 720 * 1.5 = 1382400

NV12 是什么

NV12 是一种 YUV 4:2:0 图像格式。

它不是 JPG，也不是 PNG，不能直接用普通图片查看器打开。

它由两部分组成：

Y 平面：亮度
UV 平面：色度，交错排列

对 1280x720 来说：

Y  大小 = 1280 * 720
UV 大小 = 1280 * 720 / 2
总大小 = 1280 * 720 * 1.5

所以今天生成的 1.4M 文件大小是合理的。

抓帧命令

命令：

v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=1280,height=720,pixelformat=NV12 \
  --stream-mmap=3 \
  --stream-count=1 \
  --stream-to=/tmp/frame_1280x720_nv12.yuv

含义：

  • -d /dev/video0：选择主摄像头采集节点
  • --set-fmt-video=...：设置输出格式为 1280x720 NV12
  • --stream-mmap=3：使用 mmap 方式申请 3 个缓冲区
  • --stream-count=1：只抓 1 帧
  • --stream-to=...：保存到指定文件

遇到的问题

第一次抓帧时报错：

Device or resource busy

原因是屏幕上的相机软件正在占用 /dev/video0。

处理方法：

关闭屏幕上的相机软件
重新执行抓帧命令

关闭后抓帧成功：

/tmp/frame_1280x720_nv12.yuv
大小 1.4M

把文件取回 Windows

使用 scp：

scp root@192.168.0.103:/tmp/frame_1280x720_nv12.yuv E:\RK3568\

第一次连接时会提示是否信任主机指纹，输入：

yes

Windows 上查看 NV12

安装 ffmpeg 后使用 ffplay：

ffplay -f rawvideo -pixel_format nv12 -video_size 1280x720 E:\RK3568\frame_1280x720_nv12.yuv

这条命令告诉 ffplay：

  • 这是原始视频数据，不是封装格式
  • 像素格式是 NV12
  • 分辨率是 1280x720

验证结果：

ffplay 可以正常显示画面

知识补充：节点、拓扑和 stride

状态：已验证 + 通用原理

  • sensor 是图像源，不等于 /dev/video0。
  • /dev/media0 描述 sensor、CSI、ISP 和 video node 之间的 entity、pad、link 拓扑。
  • /dev/video0 是应用进行格式协商、申请 buffer 和取帧的数据入口。
  • width height 1.5 只适用于紧密排列的 NV12；驱动可能按对齐要求提供更大的每行 stride。

因此排障顺序应是：先看 media-ctl -p 的拓扑，再看 v4l2-ctl --all 的能力和当前格式，最后抓帧验证文件大小、帧数和内容。节点存在只能证明注册完成，不能证明 sensor、链路和 ISP 都已经稳定工作。

阶段验收

  • 能指出 /dev/media0 与 /dev/video0 的职责差异。
  • 能计算 1280x720 紧密 NV12 帧的理论大小，并说明 stride 会造成偏差。
  • 能提供单帧和连续帧证据，而不是只贴命令。
  • 失败时先检查驱动/拓扑/格式，不直接跳到 OpenCV 或 RKNN。
