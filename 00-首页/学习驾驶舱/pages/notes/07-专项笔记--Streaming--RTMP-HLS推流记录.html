Nginx配置

已给 /etc/nginx/nginx.conf 增加 RTMP 配置：

rtmp {
    server {
        listen 1935;
        chunk_size 4096;

        application live {
            live on;
            hls on;
            hls_path /tmp/hls;
            hls_fragment 5s;
        }
    }
}

已给 HTTP server 增加 HLS 访问路径：

location /hls {
    types {
        application/vnd.apple.mpegurl m3u8;
        video/mp2t ts;
    }
    root /tmp;
    add_header Cache-Control no-cache;
}

注意：

/tmp/hls 必须允许 nginx worker 写入。
当前处理方式：mkdir -p /tmp/hls && chmod 777 /tmp/hls

知识补充：协议、编码、封装和延迟

状态：已验证 + 通用原理

四个概念不要混为一谈：

  • 编码器把图像压成 H.264/H.265 等视频码流。
  • 封装器把音视频码流组织成 FLV、TS 等容器/分片。
  • RTMP 是板端到服务端的推流协议。
  • HLS 是服务端把流切成 .m3u8 和分片后，播放器通过 HTTP 拉取的播放方式。

当前链路可以表示为：

检测后图像 -> 编码器 -> RTMP -> Nginx/服务端 -> HLS切片 -> ffplay

端到端延迟由采集 buffer、推理队列、编码器缓存、网络、HLS 分片时长和播放器缓存共同决定。出现“推流成功但延迟高”时，先分别记录各段延迟，不要只修改播放器参数。

阶段验收

  • 能分别说明 RTMP、HLS、H.264、FLV/TS 的层次。
  • 能确认 .m3u8 和分片确实生成，且播放器访问的是正确 IP/端口。
  • 能解释实时性与稳定性的取舍：队列丢帧降低延迟，缓冲增加稳定性。
