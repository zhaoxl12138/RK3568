  • imx415 4-001a-1: driver version: 00.01.06：IMX415 驱动实例在 I2C4、地址 0x1a 注册。
  • Detected imx415 id 0000e0：成功读取到 Sensor ID，I2C 通信和基本识别成功。
  • dphy0 matches m00_b_imx415 ... bus type 4：CSI-2 D-PHY 找到了 IMX415，并确认了总线类型。
  • Async subdev notifier completed：Sensor、CSI 和 ISP 的异步子设备绑定完成。
  • set fmt: cur_mode: 3864x2192, hdr: 0：当前使用 3864×2192、非 HDR 模式。
  • set exposure(shr0) ...：驱动已经开始设置曝光寄存器，说明不仅完成 probe，还进入了工作配置阶段。

需要理解但暂不判定为故障的提示

  • Get hdr mode failed! no hdr default：读取 HDR 模式失败后采用默认非 HDR 模式。当前 hdr: 0 且已有图像链路，因此暂不作为故障；面试时应说明 HDR 是可选模式，不等于 Sensor 没有被识别。
  • could not get sleep pinstate：设备树中没有找到 sleep pinctrl 状态。当前系统仍能完成初始化，但说明设备树电源/引脚低功耗描述可能不完整。
  • Entity type ... was not initialized：RKISP 旧内核/驱动组合中的 Media Entity 初始化提示。由于后续 Media Graph 已成功建立，当前先记录，不直接认定为阻塞问题。
  • max input:0x0@0fps：RKISP 初始化早期尚未绑定输入 Sensor，后续异步绑定完成，不应单独据此判断无图像。

需要放入 Day 2 的核查项

日志中三组供电属性没有在设备树节点中找到：

dvdd-supply ... failed

这表示驱动没有从设备树获取对应的真实 regulator，而是使用了 dummy regulator。由于你的板子目前能够识别 Sensor 并出图，硬件供电大概率由模组或板级固定电源提供，但设备树的电源描述是否完整仍需核查。后续不能直接把它改成真实 regulator，必须先对照板卡原理图、Camera 模组手册和当前设备树确认。
