阶段 00 · 系统总览

从 IMX415 到 /dev/video0

Camera 驱动不是一条单线：I2C 控制链负责“让 Sensor 能工作”，MIPI 数据链负责“把图像送进 RKISP”。两条链在 Sensor 处汇合。

打开驱动全链路图复习 Sensor 与 probe

控制链：配置和启动 Sensor

DTS → I2C Core → IMX415 driver

DTS / I2C4

提供 compatible、0x1a、clock、GPIO、供电和 endpoint 信息。

I2C Core

创建 i2c_client，比较 compatible，匹配后通过总线 probe 入口调用 Sensor 驱动。

imx415_probe()

数据链：传输和处理图像

IMX415 → D-PHY → CSI-2 → RKISP → V4L2

04 · RAW 源

IMX415 Sensor

按寄存器配置输出 SGBRG10_1X10；图像数据不经过 I2C。

05 · 物理层

MIPI D-PHY

在时钟 lane 和多条 data lane 上接收差分高速串行信号，恢复可靠比特流。

解析包头、虚拟通道和数据类型，把 RAW10 像素流交给 ISP。

RKISP

接收 RAW Bayer，完成裁剪和 ISP 处理，并产生 mainpath、selfpath 等输出。

08 · 用户态接口

Media / V4L2

Media Graph 描述实体连接，V4L2 video node 让应用申请 buffer、设置格式和抓帧。

09 · 可验证输出

/dev/video0

它是 rkisp_mainpath 暴露的采集节点，不是 IMX415 本身；当前可输出 NV12。

查看面试答案 →

调试时从哪一层开始

按证据定位，不从应用层反猜底层

没有识别到 Sensor

先查原理图、DTS、I2C 地址、上电时序、时钟、RESET/PDN 和 Sensor ID。

识别成功但没有图像

继续查 endpoint、lane 数、频率、D-PHY、CSI-2、RKISP 和 Media Graph。

有节点但应用抓帧失败

再查 video node、格式、分辨率、stride、VB2 buffer 和 stream on。
