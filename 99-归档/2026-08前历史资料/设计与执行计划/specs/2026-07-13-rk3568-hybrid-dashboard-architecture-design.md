# RK3568 混合式学习驾驶舱与知识库架构设计

## 1. 目标

把当前 RK3568 Obsidian 仓库重构为两层协作系统：

- 网页学习驾驶舱负责全局地图、当前阶段、快速跳转、证据浏览和记录入口。
- Obsidian Markdown 负责正文、任务状态、实验记录、技术知识和历史证据。

重构完成后，用户应能在一分钟内回答：

1. 当前处于哪个阶段。
2. 本轮唯一任务是什么。
3. 该阶段要理解哪些技术关系。
4. 去哪里查看实验事实和结果图片。
5. 去哪里记录复盘或实验过程。

## 2. 设计原则

### 2.1 唯一内容源

网页不复制维护 Markdown 正文。所有知识、状态和记录仍以 Obsidian 文件为准。

### 2.2 唯一状态源

`06-任务/01-下一步任务看板.md` 是当前阶段、当前任务、验收勾选和暂不做事项的唯一状态源。网页中的状态是生成结果，不手工维护。

### 2.3 单向学习路径

日常主路径固定为：

```text
网页驾驶舱 / Obsidian 首页
-> 阶段主线
-> 专项知识
-> 实验与证据
-> 项目输出
```

项目输出可以引用专项知识与实验事实，但不得反向维护当前任务。环境和资料是支撑层，归档不进入日常路径。

### 2.4 保留历史事实

实验日期、命令、输出、失败过程、图片和性能数据不因重构而丢失。被替代的入口和重复叙述先归档，不直接删除。

## 3. 目标目录架构

### `00-首页`

职责：提供网页驾驶舱、Obsidian 首页和网页生成数据。

计划结构：

```text
00-首页/
├── 00-RK3568学习主入口.md
└── 学习驾驶舱/
    ├── index.html
    ├── app.js
    ├── styles.css
    └── generated/
        └── vault-data.js
```

`generated/vault-data.js` 由生成脚本产生，不能作为人工编辑的状态源。

### `01-主线`

职责：解释系统地图、阶段顺序、阶段入口和完成标准。

处理原则：

- `01-AI视觉系统主线` 保留系统级地图。
- `02-从零到Python MVP学习路线` 拆除重复状态、长日志和专项技术正文，只保留阶段导航。
- `03-Camera-OpenCV-RKNN汇合路线` 的有效系统关系并入系统地图或系统专项笔记；历史决策移入归档。
- 增加 `00-主线入口.md`，作为主线目录的唯一 MOC。

### `02-资料`

职责：官方 PDF 和外部资料索引。

增加 `00-资料入口.md`。资料页只能说明用途、版本和适用阶段，不能维护当前进度。

### `03-环境`

职责：WSL、Ubuntu、SDK、VSCode 和工具环境。

增加 `00-环境入口.md`。环境文档记录可复现配置和已知问题，不承担项目路线。

### `04-项目`

职责：项目架构、演示手册、讲解稿和可视化页面。

现有 HTML、PNG 和项目说明保留。项目文档只描述基线、实现、验证、限制和升级方向，不维护当前任务。

### `05-实验与证据`

职责：合并实验过程和实验产物，使“发生了什么”与“证据在哪里”位于同一层。

计划结构：

```text
05-实验与证据/
├── 00-实验与证据入口.md
├── 01-板子到手验机记录.md
├── 02-每日进度记录.md
└── 实验产物/
    ├── 01-实验产物索引.md
    └── assets/
```

当前 `08-附录/实验产物` 移入该目录。所有 Wikilink、图片嵌入和相对路径同步修复。

### `06-任务`

职责：维护唯一当前状态。

任务看板固定包含：当前阶段、本轮唯一任务、阶段验收、暂不做和复盘记录。其他文档只能链接或显示生成摘要。

### `07-专项笔记`

职责：按技术域保存可复用知识。

保留现有 Camera-V4L2、OpenCV、AI-RKNN、Display-MIPI、Streaming 和系统分区。`00-专项笔记入口` 负责技术域导航，专项正文不维护全局下一步。

### `08-附录`

职责：保存资料包说明、图源和非日常参考资产。

实验产物移出后，`Excalidraw` 原始图源移入 `08-附录/图源/Excalidraw`。附录只能通过附录入口进入。

### `09-输出沉淀`

职责：文章、面试表达、专题讲解和复盘输出。

输出文档引用项目基线、专项知识和实验证据，不复制维护任务状态。

### `99-归档`

职责：保存被替代入口、历史路线和旧叙述。

活跃内容不得直接链接到某一篇归档正文；只允许通过归档入口访问历史内容。

### `docs`

职责：保存本次架构设计和实施计划。它属于维护层，不出现在学习驾驶舱的日常导航中。

## 4. 网页学习驾驶舱

### 4.1 页面模块

首页包含：

1. 当前阶段和本轮唯一任务。
2. 阶段 0–10 的状态地图。
3. AI Camera 数据流节点。
4. Camera、OpenCV、RKNN、显示、推流等技术域入口。
5. 实验产物画廊和关键证据入口。
6. 项目演示和输出入口。
7. 打开任务看板、每日记录和阶段复盘的快捷动作。

### 4.2 跳转方式

- Markdown 使用 `obsidian://open?vault=RK3568&file=...` 深链接。
- 现有 HTML、PNG 和图片使用相对路径。
- 页面提供清晰的降级提示：若 Obsidian 深链接未注册，则显示目标文件路径供手动打开。

### 4.3 数据生成

新增生成脚本读取：

- `06-任务/01-下一步任务看板.md`
- `07-专项笔记/系统/AI Camera分阶段验收标准.md`
- `08-附录/实验产物/01-实验产物索引.md`，迁移后改为新路径
- 主线、专项和项目入口文件清单

脚本输出 `00-首页/学习驾驶舱/generated/vault-data.js`。使用 JavaScript 文件而不是运行时 `fetch` JSON，使页面可以直接以本地文件打开，无需常驻服务器。

### 4.4 记录边界

网页不直接写 Markdown。快速记录按钮只打开以下 Obsidian 文件：

- 当前任务：`06-任务/01-下一步任务看板.md`
- 时间线：`05-实验与证据/02-每日进度记录.md`
- 阶段验收：`07-专项笔记/系统/AI Camera分阶段验收标准.md`

这样既提高入口效率，又不会引入写入 API、并发冲突和第二套状态。

## 5. 文档关系规则

### 5.1 入口层

README 面向 GitHub 访客；Obsidian 首页和网页驾驶舱面向日常学习。三者可以摘要当前成果，但当前任务必须指向任务看板。

### 5.2 主线层

每个阶段只保留：目标、前置、必懂概念、专项入口、证据入口和完成标准。操作日志下沉到实验层，技术解释下沉到专项层。

### 5.3 专项层

每篇专项笔记至少链接一个主线阶段和一个证据入口。专项笔记中的“下一步”改为历史决策或删除，避免产生第二任务源。

### 5.4 证据层

证据记录必须说明所属阶段、首次验证日期、最近复测日期和对应知识笔记。证据可以保留历史状态，但必须明确标记为历史。

### 5.5 输出层

输出只组织叙事，不重新定义事实。性能、版本和完成情况引用项目基线或实验产物索引。

## 6. 迁移策略

1. 先建立文件和链接基线。
2. 创建各目录入口页和驾驶舱文件，不立即删除原入口。
3. 移动实验产物与 Excalidraw 图源并同步修复链接。
4. 收敛三篇主线的职责和重复内容。
5. 清理活跃文档中的重复状态及过时“下一步”。
6. 生成网页数据并完成驾驶舱。
7. 验证 Obsidian 深链接、HTML、图片和内部 Wikilink。
8. 将被替代文档移入归档。

已有未提交修改必须保留。发生内容重叠时，应先比较差异，不能覆盖用户改动。

## 7. 错误处理与恢复

- 文件移动前记录源路径、目标路径和所有引用位置。
- 迁移采用小批次，每批完成后检查断链。
- 生成脚本遇到缺失字段时保留安全默认值，并在输出中列出警告。
- 网页找不到目标时显示文件路径，不静默失败。
- 不删除历史文件；被替代内容先移入 `99-归档/重构前`。
- 不使用破坏性 Git 回退命令。

## 8. 验证方案

### 8.1 结构验证

- 每个活跃顶层目录有唯一入口页。
- 根目录和活跃目录中不存在职责不明的孤立笔记。
- 实验记录和实验产物位于同一证据层。

### 8.2 链接验证

- Wikilink 目标存在。
- Markdown 相对链接、图片嵌入和 HTML/PNG 入口有效。
- 活跃文档不直接依赖已归档路径。
- Obsidian 深链接正确编码中文路径。

### 8.3 状态验证

- 完整当前状态只出现在任务看板。
- 网页展示值由任务看板生成。
- 主线、项目、专项和输出中的状态只能是摘要或历史标记。

### 8.4 网页验证

- `index.html` 可直接本地打开。
- 当前阶段、任务、阶段地图和技术域能够显示。
- Markdown 按钮能打开对应 Obsidian 文件。
- 图片和现有可视化页面能够访问。
- 页面在常见桌面宽度和窄窗口下可用。

### 8.5 内容完整性

- 实验日期、命令、日志、截图和性能数字没有丢失。
- 当前项目基线仍为 YOLOv5 RKNN Python MVP。
- YOLOv8n、C++、Linux 5.10 等后续目标没有被误写为已完成。

## 9. 不在本轮范围

- 网页直接编辑 Markdown。
- 部署公网网站。
- 修改外部代码仓库或板端程序。
- 自动解析所有 Markdown 正文并生成完整知识站。
- 新增登录、云同步、数据库或后端服务。
- 重做现有 HTML 可视化和 Excalidraw 图形内容。
