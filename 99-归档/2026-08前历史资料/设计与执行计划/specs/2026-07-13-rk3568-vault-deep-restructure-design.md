# RK3568 学习库深度重构设计

## 目标

把当前仓库从“项目过程资料集合”重构为一套可持续复盘的 RK3568 AI Camera 知识库。重构不只调整目录，还要完善正文内容，使读者能够回答四类问题：

1. 系统的数据怎样从 Camera 流到显示和网络端。
2. V4L2、GStreamer、OpenCV、RKNN、MIPI、RTMP/HLS 各自负责什么。
3. 每个阶段怎样验证成功，失败时怎样定位问题。
4. 哪些结论来自实际验证，哪些是通用原理，哪些仍待验证。

## 保留原则

- 现有未提交修改视为用户成果，不回退、不覆盖。
- 被合并或替代的旧文档移入 `99-归档`，不直接删除。
- 实验时间、命令、输出、路径和失败记录属于原始证据，不为追求整洁而改写事实。
- Excalidraw 原始文件和现有 HTML/PNG 可视化不重制，只整理入口与说明。
- 正式源码仍由外部代码仓库承担，本仓库只保存必要片段、运行方式和结论。

### 知识层

专项笔记按技术域承载可复用知识：

- Camera / V4L2：sensor、MIPI CSI、D-PHY、CIF、ISP、Media Controller、video node、像素格式、缓冲队列。
- GStreamer / OpenCV：pipeline 协商、caps、颜色转换、appsink、OpenCV backend、零拷贝边界。
- AI / RKNN：模型转换与 runtime 的边界、输入布局和量化、前处理、NPU 推理、后处理、坐标映射。
- Display / MIPI：DRM/KMS 或 framebuffer 的角色、方向和分辨率、显示链路与推理链路的耦合点。
- Streaming：编码、封装、协议、服务端和播放器的区别，RTMP 到 HLS 的延迟来源。

## 内容补充范围

### 系统全景

新增一篇“AI Camera 系统数据流与模块边界”，明确控制流与数据流的区别，并给出如下主链：

```text
IMX415 sensor
-> MIPI CSI-2 / D-PHY
-> CIF / ISP
-> V4L2 video node
-> GStreamer
-> OpenCV / NumPy
-> resize / color / layout / quantization
-> RKNN Runtime / NPU
-> decode / NMS / coordinate mapping
-> overlay
-> local display and/or encoder
-> RTMP server / HLS segments
-> Windows player
```

### 阶段验收标准

每阶段至少给出：

- 可观察输入和输出。
- 最小成功证据。
- 关键参数及其来源。
- 失败时的第一检查点。
- 与下一阶段的接口约束。

成功标准应从“命令没有报错”提升为“输出尺寸、格式、帧数或检测结果可验证”。

### 故障排查

新增总排障索引，并在专题笔记中保留具体分支：

```text
没有设备节点
-> 先查驱动、设备树和 media topology

节点存在但抓不到帧
-> 再查链路状态、格式、分辨率、帧率和 buffer

V4L2 能抓帧但 OpenCV 失败
-> 再查 backend、caps、颜色转换和 appsink

图像正常但推理异常
-> 再查 resize、RGB/BGR、NHWC/NCHW、量化和模型输入

推理正常但框位置错误
-> 再查 letterbox、缩放比例、padding、解码和坐标回映

本地正常但网络播放失败
-> 再查编码器、封装、服务端、端口、播放地址和缓存
```

### 知识状态标记

重要结论采用三类标记：

- `已验证`：有本项目命令、日志、图片或产物支撑。
- `通用原理`：来自稳定技术机制或官方资料，但不代表已在当前板卡逐项验证。
- `待验证`：合理假设或后续任务，不写成既成事实。

### 关键知识补充

首轮至少补齐以下容易混淆的关系：

- `/dev/video0` 不是 Camera 本身，而是内核暴露的数据节点。
- Media Controller 描述实体和 pad/link 拓扑，V4L2 video node 负责面向应用的数据流接口。
- NV12 的 Y 平面与交错 UV 平面、字节大小计算和 stride 风险。
- GStreamer pipeline 中 caps 协商失败的典型原因。
- OpenCV 读取失败不等于底层 Camera 失败，应分层验证。
- RKNN Toolkit、RKNN Runtime、RKNNLite 和 NPU 驱动之间的边界。
- 模型前处理必须与转换/训练配置一致，尤其是颜色顺序、布局、归一化和量化。
- YOLO 后处理中的候选框解码、置信度筛选、NMS 和坐标回映。
- MIPI Camera 与 MIPI Display 是两条不同链路，不因都叫 MIPI 而直接相连。
- RTMP、HLS、编码格式和容器格式属于不同层次。
- 端到端延迟由采集、缓存、推理、编码、网络、切片和播放器缓冲共同构成。

- 首页可以在一分钟内回答“当前做到哪里、下一步做什么、去哪里查细节”。

- 同一条“当前状态”只在任务看板维护，其他文档不再产生冲突版本。
- 核心技术链每一层都有职责、输入输出、验证方法和排障入口。
- 已验证事实、通用原理和待验证事项能够被区分。
- 被替代内容已归档，实验事实无丢失。
- Obsidian 双链和相对文件链接不存在已知断链。
- 新增内容不把未经验证的板卡细节写成实测结论。
